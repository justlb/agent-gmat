# RF-COMLINK Input Contract

This document defines the only authorised sources for an RF-COMLINK execution.
An execution belongs to **one GMAT run**. It must never combine radio
parameters, ground-station geometry, CIC files, or results from another run.

```text
satellite.json from the run ───────────┐
Simu-CIC definition + CIC/Sat files ───┼─> RF-COMLINK input manifest ─> prepared .rfcl scenario
RF-COMLINK template station database ──┘
```

RF-COMLINK remains the authority for the link-budget calculation. The backend
prepares an auditable scenario; it does not invent radio or geometry values.

## 1. Dynamic source: Simu-CIC output from the same run

The CIC directory must have been generated by Simu-CIC for the selected run:

```text
<run>/opalis/02-simu-cic/02-fichiers-cic/Sat/
```

The executed Simu-CIC definition is also required:

```text
<run>/opalis/02-simu-cic/simucic.definition.json
```

For a selected ground station at index `<n>` in the executed Simu-CIC
definition, RF-COMLINK requires the following non-empty files:

| RF-COMLINK data | CIC file | Required |
| --- | --- | --- |
| range during a pass | `Sat_DISTANCE_GROUND_STATION_<n>.TXT` | yes |
| visibility during a pass | `Sat_GEOMETRICAL_VISIBILITY_GROUND_STATION_<n>.TXT` | yes |
| elevation / spacecraft direction | `Sat_SATELLITE_DIRECTION-GROUND_STATION_<n>_FRAME.TXT` | yes |

The executed Simu-CIC attitude mode must be `ground_station_tracking`, and the
selected RF ground station must appear in its executed `ground_stations` list.
The visibility file must contain at least one visible sample. A configured
station without a visible pass blocks scenario preparation; RF-COMLINK must
not report an artificial zero-availability result in that case.

The backend derives the following run geometry only from positive-elevation,
visible CIC samples:

| Derived value | Method | Stored path |
| --- | --- | --- |
| mean range | arithmetic mean of distance samples during visible passes | `analysis_requests.rf_comlink.run_geometry.mean_range_km` |
| mean elevation | arithmetic mean of positive-elevation samples during visible passes | `analysis_requests.rf_comlink.run_geometry.mean_elevation_deg` |
| sample count | number of CIC samples used for the means | `analysis_requests.rf_comlink.run_geometry.sample_count` |
| source files | exact CIC files used | `analysis_requests.rf_comlink.run_geometry.source_files` |

The scenario builder embeds converted copies of these CIC files in the `.rfcl`
package. It converts Simu-CIC MJD timestamps to the UTC form expected by
RF-COMLINK; it does not substitute values from another ephemeris or a template.

## 2. Static source: run-local satellite.json

The only source of spacecraft radio inputs is the run snapshot:

```text
<run>/satellite.json
```

The satellite library is not a direct RF-COMLINK input. Its values must already
have been copied into the snapshot that belongs to the run. Missing values stay
missing: the adapter blocks preparation and records their paths in the input
manifest instead of filling them from an example `.rfcl` file.

### Data handling

| Data | Path in satellite.json | Unit | Required |
| --- | --- | ---: | --- |
| initial memory usage | `satellite.bus.rf_comlink.data_handling.initial_memory_usage_bits` | bits | yes; must be >= 0 |
| memory capacity | `satellite.bus.rf_comlink.data_handling.memory_capacity_bits` | bits | yes; must be > 0 and >= initial usage |
| payload mode | `satellite.bus.rf_comlink.data_handling.payload_binary_rate.mode` | `none` or `periodic` | yes |
| payload rate | `satellite.bus.rf_comlink.data_handling.payload_binary_rate.rate_bps` | bit/s | required when mode is `periodic` |
| active duration | `satellite.bus.rf_comlink.data_handling.payload_binary_rate.active_duration_s` | s | required when mode is `periodic`; must not exceed repeat period |
| repeat period | `satellite.bus.rf_comlink.data_handling.payload_binary_rate.repeat_period_s` | s | required when mode is `periodic` |

For periodic payload generation, the backend writes a CIC rate profile on the
time grid from the selected distance CIC file. The profile is used only for the
payload downlink and remains aligned to the run's Simu-CIC timeline.

### Radio links

Each entry in `satellite.bus.rf_comlink.links[*]` defines one RF-COMLINK link.
The generator must create only the links declared here; unused links from the
empty RF-COMLINK template are removed.

| Data | Path for link `<i>` | Unit / values | Required |
| --- | --- | --- | --- |
| identifier | `links[i].id` | text | yes |
| display name | `links[i].name` | text | yes |
| direction | `links[i].direction` | `EarthSpace` or `SpaceEarth` | yes |
| station-tracking requirement | `links[i].requires_ground_station_tracking` | boolean | yes |
| frequency band | `links[i].system.frequency_band` | text, for example `S` or `X` | yes |
| frequency | `links[i].system.frequency_mhz` | MHz, > 0 | yes |
| binary rate | `links[i].system.data_rate_bps` | bit/s, > 0 | yes |
| bit error rate | `links[i].system.bit_error_rate` | > 0 | yes |
| modulation | `links[i].system.modulation` | text | yes |
| required Eb/N0 | `links[i].system.required_ebn0_db` | dB | optional |
| spacecraft antenna role | `links[i].spacecraft_antenna.role` | text | yes |
| spacecraft transmitter EIRP | `links[i].spacecraft_antenna.eirp_dbw` | dBW | one of this or `system.transmit_power_dbm` is required for `SpaceEarth` |
| spacecraft receiver G/T | `links[i].spacecraft_antenna.figure_of_merit_db_per_k` | dB/K | one of this or `system.receiver_sensitivity_dbm` is required for `EarthSpace` |
| antenna gain / losses | `links[i].spacecraft_antenna.gain_db`, `pointing_loss_db`, `axial_ratio_db` | dB | optional when the applicable RF-COMLINK model supports them |
| propagation assumptions | `links[i].propagation.*` | loss / weather fields | optional |

When `requires_ground_station_tracking` is true, the configuration must select
a Simu-CIC ground station. If exactly one station is configured, it becomes the
RF selection automatically; with multiple stations,
`analysis_requests.rf_comlink.selected_ground_station_id` is required. The
selected station must be one of
`analysis_requests.simu_cic.ground_station_ids`.

## 3. Properties owned by the RF-COMLINK template and station database

The base scenario is the configured RF-COMLINK template (by default
`example/vide.rfcl`). It owns the RF-COMLINK XML structure and the station
database layout.

Ground-station hardware is resolved from the station database packaged with the
selected template. The backend selects a record for the station and frequency
band of **each link**. It copies the resolved station code, location, antenna,
EIRP, G/T, gain, pointing-loss, and axial-ratio distributions into the
prepared scenario. It must never reuse a station record of a different band or
silently substitute another station. A missing matching record must block
preparation; this explicit preflight check is an outstanding implementation
requirement and must be added before relying on a new station or band.

For a downlink (`SpaceEarth`), ground receiving hardware comes from that
database. For an uplink (`EarthSpace`), ground transmitting hardware comes
from the same database. Spacecraft antenna values are used only on the
spacecraft side of the link.

The backend calculates a per-link system temperature for the prepared scenario:

- for an uplink receiver, it derives the value from spacecraft antenna gain and
  G/T when both are present; otherwise it uses the documented conservative
  fallback of 300 K;
- for a downlink receiver, it uses 250 K in X band and 150 K otherwise.

These values are recorded under
`analysis_requests.rf_comlink.run_geometry.system_temperature_k_by_link` with
the method and CIC source files. They are run-scoped preparation values, not
satellite-library defaults.

## 4. Resolved input manifest and scenario

Before building an RF-COMLINK scenario, the backend writes this immutable,
run-local manifest:

```text
<run>/rf-comlink/01-input/rf-comlink-inputs.json
```

It is the interface between TypeScript and the Python scenario generator. It
contains at least:

```json
{
  "schema_version": 1,
  "source_satellite": "satellite.json",
  "source_simu_cic_definition": "opalis/02-simu-cic/simucic.definition.json",
  "selected_ground_station_id": "<station id>",
  "cic_inputs": [
    "opalis/02-simu-cic/02-fichiers-cic/Sat/Sat_DISTANCE_GROUND_STATION_<n>.TXT"
  ],
  "data_handling": {},
  "links": [],
  "run_geometry": {
    "mean_range_km": 0,
    "mean_elevation_deg": 0,
    "sample_count": 0,
    "source_files": []
  },
  "validation": { "status": "ready", "missing": [], "warnings": [] }
}
```

The Python generator accepts this manifest and produces:

```text
<run>/rf-comlink/02-scenario/prepared-rf-comlink.rfcl
```

The frontend must not construct `.rfcl` XML or pass a manual series of radio
parameters to the Python process.

## 5. Pre-launch validation rules

RF-COMLINK may be prepared only if:

1. Simu-CIC completed for the same run;
2. the executed Simu-CIC definition uses ground-station tracking and contains
   the selected station;
3. all three required CIC files for that station exist, are non-empty, and
   contain at least one visible sample;
4. `satellite.json` for the same run provides a complete, valid data-handling
   block and at least one complete radio link;
5. all required numeric values are finite and satisfy the ranges in this
   contract;
6. the selected ground station is configured for Simu-CIC and has a matching
   RF-COMLINK database record for every link band (the current generator needs
   an explicit preflight check to enforce this rule);
7. `rf-comlink-inputs.json` is saved with `validation.status = "ready"`
   before the scenario is generated.

When changing this contract, update the TypeScript adapter, preparation routes,
Python scenario generator, and focused RF-COMLINK tests together. Do not infer
inputs from a previous run, a report, or an example scenario.

## 6. Results boundary

The calculation result is saved separately under:

```text
<run>/rf-comlink/03-results/rf-comlink-results.json
```

It is not an input to scenario preparation. Link-budget values are accepted
only when the saved result extractor finds populated, recognised report data.
The raw report and calculated `.rfcl` package remain the authoritative evidence
for any engineering conclusion.
